# Pi 1.5.0 `/clone`, independent dispatch, and cache identity

Research for [issue #14](https://github.com/wh3at/pi-orca-dispatch/issues/14), against Pi v1.5.0 at the fixed commit [`f9a26365568127461c47a07a37dcb42c140a3ac5`](https://github.com/earendil-works/pi/tree/f9a26365568127461c47a07a37dcb42c140a3ac5); the [official tag ref](https://api.github.com/repos/earendil-works/pi/git/ref/tags/v1.5.0) identifies that commit. Dispatch comparison is pinned to [`7839a3cbd83d2e551f9ae7ea93282a5b28625564`](https://github.com/wh3at/pi-orca-dispatch/tree/7839a3cbd83d2e551f9ae7ea93282a5b28625564). Pi links below are immutable source/doc citations; provider documentation is live. This is research, not an approved design.

**Constraints:** The user requires independent conversations and no parent mutation, not different UUIDs. Real provider cache measurement is **impossible**, not optional or a future acceptance prerequisite. No model/API requests were made. No private sessions, logs, settings, or auth were read. No implementation, configuration, or issue was changed. No relevant root glossary or ADR exists.

## Decisive answers

1. **Pi really has `/clone`.** It copies the current active path through the current leaf to a new session, then **switches the current interactive process** to that session. It is not a command to leave the parent running unchanged and start a second process. An extension can cancel it; an empty leaf is rejected. See [CLI handler](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L5640-L5658), [runtime implementation](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/agent-session-runtime.ts#L262-L350), and [official workflow](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/sessions.md#L30-L44).
2. Official `/clone` **generates a fresh UUIDv7** and a distinct session file in persisted mode; it does not reuse the parent's session ID. That is this operation's implementation, **not a proof that separate UUIDs are intrinsically required for independent conversation**. Storage separation, correct routing and ownership matter; reusing IDs has important discovery, resource and transport risks discussed below. [ID generator](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L264-L266); [clone header and file](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1681-L1693).
3. **Public APIs exist for related operations, but not a single documented parent-preserving live-runtime clone-and-spawn API.** Extension `ctx.fork(leaf, { position: "at" })`, SDK `AgentSessionRuntime.fork`, and RPC `clone` replace the caller's current session. The exported SDK `SessionManager.open(...).createBranchedSession(leaf)` can operate on a separately opened manager and produce the same type of persisted active-path file without switching the *live* manager; it is a lower-level composable public method, not the full CLI lifecycle nor a guarantee of a complete live snapshot. SDK `forkFrom` and CLI `--fork` also create separate file-backed sessions but copy the **whole source file tree**, not the live active branch operation. See the detailed limitations below.
4. The new ID propagates to Pi's provider stream `sessionId`. For OpenAI Responses and Codex, Pi ordinarily derives `prompt_cache_key` from it; changing IDs can affect cache grouping. Anthropic direct uses cache-control blocks and Gemini/Vertex request builders have no analogous Pi-session-ID cache key; **do not introduce a common cache-key mechanism for Anthropic/Google**. Cache hits are neither established nor guaranteed by these source findings. **No dispatch change is an acceptable outcome**; no policy or implementation change follows automatically.

## What `/clone` actually copies and replaces

* The CLI reads `getLeafId()`, calls `runtimeHost.fork(leafId, { position: "at" })`, clears editor text on success, and displays the new-session status. The RPC `clone` performs the same fork and rebinds its session; it returns only cancellation status, and errors without a current leaf ([interactive](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L5640-L5658), [RPC](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L619-L628)).
* `getBranch` walks root-to-leaf including all entry types, not just user/assistant messages. Only the selected path is copied, not abandoned branches. Non-label entries keep their entry IDs and content; parent links are rechained after removing label entries, and affected compaction references adjusted. Resolved labels for included entries are reconstructed as new label entries at the end, even if the relevant label was elsewhere in the source tree. Raw copied entries are not the same thing as the model-visible request: Pi reconstructs a compaction-aware projection ([branch](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1475-L1510), [copy and labels](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1638-L1723), [projection](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L560-L583)).
* The new header contains the new ID, timestamp, cwd, and (only for a persisted source) `parentSession` pointing to the source path. For a persisted manager Pi switches its manager to the new file; it writes immediately if the path contains a conversation, otherwise defers until persistence rules permit. In-memory clone has no file and replaces the in-memory manager's contents, also with a new ID ([creation](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1681-L1758)).
* A persisted source is reopened from disk at the selected ID. If it has no saved file, Pi rejects cloning even if a leaf exists. After creating the branch file, Pi aborts/settles outgoing work, emits shutdown, disposes the old runtime, creates the replacement, reloads/rebinds extensions, and emits `session_start` reason `fork`. Therefore the old file normally remains a separate source, but `/clone` is **not a strict no-mutation operation**: teardown can settle/persist an aborted turn and extension shutdown hooks have effects. There is no simultaneous untouched parent runtime left behind ([runtime](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/agent-session-runtime.ts#L167-L177), [fork path](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/agent-session-runtime.ts#L289-L349), [extension lifecycle](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/extensions.md#L515-L530)).

## Model, tools and runtime state

The branch contains model and thinking entries and system/tool declarations as conversation history, but clone **reconstructs** rather than serializes a running process. On creation Pi resolves model from explicit options or branch selection if the model and configured authentication are available, otherwise falls back; thinking comes from an explicit option or saved branch/defaults and is clamped to model capabilities. The agent's initial messages come from the reconstructed projection. Tool activation starts from explicit options or configured defaults and newly loaded registrations; saved tool declarations are transcript data, not proof that every live tool and its exact implementation/order were snapshotted. Runtime creation and extension reload can alter state, prompts and behavior. [Session format](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/session-format.md#L78-L102), [model/thinking](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/sdk.ts#L209-L277), [tool selection](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/sdk.ts#L280-L294), [agent construction](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/sdk.ts#L403-L438).

Disposal aborts work, invalidates old extension contexts, cancels cache warming and cleans session resources. Extension variables, pending activity, transport sockets, captured payloads and other process-local state are not copied by the path-copy operation. Runtime recreation may reuse configured inputs, but this is not a live-memory clone ([dispose](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/agent-session.ts#L1424-L1449), [runtime factory](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/agent-session-runtime.ts#L28-L41)).

## Public surfaces versus internal composition

| Surface | What it provides | Parent-preserving separate-process dispatch? |
|---|---|---|
| Interactive `/clone` | Active path, new ID, switch current runtime | **No**: replaces current session, no child process. |
| Extension `ctx.fork(id, {position: "at"})` | Documented clone equivalent; `withSession` receives replacement context | **No**: switches current runtime; extension's `sessionManager` interface exposes read operations, not `createBranchedSession` ([extension docs](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/extensions.md#L1381-L1405), [read-only type](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L245-L262)). |
| RPC `clone` / SDK `AgentSessionRuntime.fork` | Equivalent runtime replacement in that host | **Not on the live parent host**; a separate host would itself need a valid initial snapshot. [SDK docs](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/sdk.md#L34-L60). |
| Exported SDK `SessionManager.open(path, dir).createBranchedSession(leafId)` | Independently opened manager uses the same lower-level path-copy code as `/clone`; returns child path, changes that manager, not the live manager | **Composable for a saved, up-to-date source**, not a one-call spawn or a full snapshot. Reopening can load/migrate source; active leaf must be supplied and present on disk; a memory-only/unsaved parent is not covered; global labels and timing must be considered. SDK docs direct callers to exported declarations/source for methods. [export](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/index.ts#L280-L305), [open/migration](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1086-L1101), [open](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1771-L1796), [SDK reference](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/sdk.md#L34-L52). |
| CLI `--fork <path>` / exported `SessionManager.forkFrom` | New independent file, all non-header source-file entries; default new ID, optionally caller-selected ID | **Possible building block for saved file-backed work**, but not `/clone`'s selected active-path semantics or live-state capture; it does not spawn and initialize dispatch on its own. [CLI](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/cli.md#L90-L107), [implementation](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1819-L1881). |

The exported SDK also supports constructing in-memory managers and supplying them to `createAgentSession`; that is host composition, not a promise of an independent file-backed clone of an arbitrary live extension runtime. Official `/clone` itself uses the lower-level manager method on a separately opened manager for persisted sources, then replaces the runtime ([SDK](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/sdk.md#L38-L52), [runtime](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/agent-session-runtime.ts#L312-L329)).

## Identity, cache keys and transport are different things

* Session IDs are UUIDs by default, but SDK and CLI permit explicit IDs; a UUID is not the conversation tree's entry ID or the file path. `--fork --session-id` allows a chosen new ID, but CLI checks for an existing ID in the target lookup scope. Duplicate IDs can make ID-based discovery ambiguous; SDK's `findById` returns the first matching header. File separation can make transcripts independent even with the same ID, but duplicate IDs are not thereby universally safe. This is a conceptual distinction, **not a recommendation to reuse an ID** ([format](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/docs/session-format.md#L8-L14), [CLI target check](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/main.ts#L368-L383), [discovery](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/session-manager.ts#L1889-L1903)).
* Pi's coding-agent initializes the Agent's `sessionId` from its session manager; the agent forwards that and its configured `transport` in loop options. The lower-level public stream option explicitly says providers may use session ID for cache, routing or other session-aware features, and may ignore it. Thus overriding or reusing it is **not merely an isolated cache-key change** ([SDK](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/coding-agent/src/core/sdk.ts#L403-L436), [agent](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/agent/src/agent.ts#L476-L486), [option contract](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/types.ts#L242-L257)).
* **OpenAI Responses API:** absent `cacheRetention: "none"`, Pi sends a clamped session ID as `prompt_cache_key`, and depending on compatibility sends related request/affinity headers. OpenAI's [cache-key documentation](https://developers.openai.com/api/docs/guides/prompt-caching#prompt-cache-keys) describes key-based grouping/routing, not a guaranteed cache hit. The same key alone cannot establish identical request prefixes or cache availability ([request](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-responses.ts#L360-L370), [headers](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-responses.ts#L301-L327)).
* **OpenAI Codex subscription path:** Pi also uses the session-derived ID for `prompt_cache_key`, `session-id` and request headers; with `none`, it omits the cache ID and uses a generated WebSocket request ID. Transport can be SSE or WebSocket and has session-specific fallback. The in-process WebSocket map is keyed by session ID and account, and may retain connection-scoped continuation/`previous_response_id` only when request and prefix checks pass. Separate processes do not share that map/socket; same IDs in one process may also interact with cleanup. A matching key is not a cloned transport session or proof of provider-side hit ([construction](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-codex-responses.ts#L280-L316), [body](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-codex-responses.ts#L568-L580), [headers](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-codex-responses.ts#L1681-L1718), [socket reuse](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-codex-responses.ts#L1184-L1247), [continuation checks](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-codex-responses.ts#L1442-L1493), [cleanup](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/openai-codex-responses.ts#L966-L982)).
* **Anthropic direct Messages:** Pi builds cache-control markers, not an OpenAI-style common cache key. Its adapter can send an ID in compatibility-specific affinity headers; do not generalize a direct-provider result to compatible or OAuth routes ([builder](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/anthropic-messages.ts#L1153-L1183), [conditional affinity](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/anthropic-messages.ts#L1064-L1077), [Anthropic caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)).
* **Google Gemini and Vertex GenerateContent:** the ordinary Pi request builders supply model, content, system/tools and thinking config, without the Pi session ID or an explicit cached-content name. Google's [implicit caching docs](https://ai.google.dev/gemini-api/docs/caching) describe prefix-based caching subject to eligibility. A different Pi UUID alone is not evidence of a miss; it is not evidence of a hit either ([Gemini](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/google-generative-ai.ts#L370-L423), [Vertex](https://github.com/earendil-works/pi/blob/f9a26365568127461c47a07a37dcb42c140a3ac5/packages/ai/src/api/google-vertex.ts#L475-L528)).

## Comparison with current dispatch

* [`src/session.ts:121–145`](https://github.com/wh3at/pi-orca-dispatch/blob/7839a3cbd83d2e551f9ae7ea93282a5b28625564/src/session.ts#L121-L145) snapshots the live read-only manager's active branch into JSON before I/O; it does not open the parent file or switch it and works with an unpersisted source. [`writeSnapshot`](https://github.com/wh3at/pi-orca-dispatch/blob/7839a3cbd83d2e551f9ae7ea93282a5b28625564/src/session.ts#L148-L206) generates its own UUID, preserves branch entry IDs and original label entries, appends a `session_info` title, and exclusively creates a private child JSONL; unlike official clone it does not reconstruct resolved labels outside the path or rewrite label parent chains. It validates compaction references; the known retain-none self-reference rejection is outside this research scope.
* [`src/dispatch.ts:56–104`](https://github.com/wh3at/pi-orca-dispatch/blob/7839a3cbd83d2e551f9ae7ea93282a5b28625564/src/dispatch.ts#L56-L104) captures live model identity and active tool names, writes a child session/job and launches a separate Pi with explicit `--session`, provider/model, thinking and observer. The task adds new content to the child's later conversation, not the parent. It inherits selected resource flags, not the entire runtime or last provider payload. [`src/launch-plan.ts:8–32`](https://github.com/wh3at/pi-orca-dispatch/blob/7839a3cbd83d2e551f9ae7ea93282a5b28625564/src/launch-plan.ts#L8-L32) makes the allowlist explicit.
* [`observer.ts:151–163,202–235`](https://github.com/wh3at/pi-orca-dispatch/blob/7839a3cbd83d2e551f9ae7ea93282a5b28625564/observer.ts#L151-L163) checks model identity and available tool names, restores the selection, gates initial work, and detaches on session replacement. It compares the owning file path and does not report later `/clone` work as the original job ([path/status](https://github.com/wh3at/pi-orca-dispatch/blob/7839a3cbd83d2e551f9ae7ea93282a5b28625564/observer.ts#L73-L81), [detach](https://github.com/wh3at/pi-orca-dispatch/blob/7839a3cbd83d2e551f9ae7ea93282a5b28625564/observer.ts#L202-L218)). Tool-name restoration does not prove identical schemas/order or serialized prompt.

## Corrections and remaining unknowns

* Both prior reports omitted official `/clone`; their conclusions must be read with the replacement and lower-level SDK distinctions above. The earlier dispatch-compaction report's phrase “active persisted branch” is too narrow: dispatch captures the manager's **in-memory active branch**, including for unpersisted parents. Its point that dispatch does not copy a running cached-compaction capture remains consistent with clone's reconstruction. The earlier provider report correctly qualified ID effects by route; neither report is an approved design.
* No conclusion here establishes whether any specific clone or dispatch actually hits provider cache, achieves a saving, or serializes an identical prefix. Provider-side cache behavior, runtime changes and exact request equality remain unknown. Actual provider cache measurement is **impossible** in this task and must not be presented as optional validation or a release condition. Source-level reasoning and non-provider tests are distinct from proving cache benefit.
* Equal IDs would involve lookup, job ownership, session-resource cleanup, provider routing and transport interactions; the source evidence does not establish a safe same-ID dispatch design. Conversely, different UUIDs are not a user requirement or an inherent mathematical condition of independent conversations. No change, including no common mechanism for Anthropic/Google, is needed merely because `/clone` exists.
